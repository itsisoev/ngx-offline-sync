# Retry Policy

**[← Назад к конфигурации](index.md)**

> Автоматические повторные попытки для временных ошибок

**Документация:** Русский · [English](../../en/configuration/retry.md)

---

Библиотека автоматически повторяет запросы, которые завершились временной ошибкой.

Retry помогает переживать временные проблемы с сетью или сервером без необходимости повторять запрос вручную.


---

## Как работает Retry

Для каждого запроса библиотека отслеживает количество попыток и рассчитывает задержку перед следующей попыткой.

По умолчанию используется **линейная задержка**:

```text
Попытка 1 → 5 секунд
Попытка 2 → 10 секунд
Попытка 3 → запрос завершён окончательно
```

Задержка рассчитывается по формуле:

```text
delay = baseDelay × attempt
```

Например, при стандартной конфигурации (`baseDelay = 5000 ms`):

```text
attempt 1 → 5000 ms
attempt 2 → 10000 ms
```

После достижения максимального количества попыток запрос удаляется из очереди.

---

## Конфигурация

Retry можно настроить через `provideOfflineSync()`:

```ts
provideOfflineSync({
  retry: {
    maxAttempts: 5,
    delay: 3000,
  },
})
```

## 📋 Доступные опции

| Опция         | Тип      | По умолчанию | Описание                                                    |
|---------------|----------|--------------|-------------------------------------------------------------|
| `maxAttempts` | `number` | `3`          | Максимальное количество попыток отправки запроса            |
| `delay`       | `number` | `5000`       | Базовая задержка между повторными попытками в миллисекундах |

**Пример:**

```ts
provideOfflineSync({
  retry: {
    maxAttempts: 5,
    delay: 3000,
  },
})
```

даст следующую последовательность:

```text
Попытка 1 → ошибка → 3 секунды
Попытка 2 → ошибка → 6 секунд
Попытка 3 → ошибка → 9 секунд
Попытка 4 → ошибка → 12 секунд
Попытка 5 → ошибка → окончательная ошибка
```

---

## ❗ Какие ошибки повторяются

Retry применяется к ошибкам, которые могут быть временными. В частности:

- сетевые ошибки;
- 5xx ошибки сервера.

> ⚠️ Ошибки клиента, например `401` или `404`, **не повторяются** автоматически.

---

## Хранение Retry в очереди

При возникновении ошибки запрос остаётся в очереди со статусом `PENDING`.

Библиотека сохраняет:

```json
{
  "attempts": 1,
  "nextRetryAt": 1750000000000
}
```

`nextRetryAt` определяет момент, когда запрос может быть обработан снова.

После завершения текущей синхронизации библиотека автоматически планирует следующую попытку.

Пользователю не нужно обновлять страницу или повторно отправлять запрос вручную.

---

## Успешная синхронизация

Если повторная попытка завершается успешно, запрос удаляется из очереди:

```text
PENDING
   ↓
SYNCING
   ↓
SUCCESS
   ↓
удаление из очереди
```

---

## Окончательная ошибка

Если запрос не удалось выполнить после всех разрешённых попыток, он удаляется из очереди:

```text
PENDING
   ↓
RETRY
   ↓
RETRY
   ↓
FAILED
   ↓
удаление из очереди
```

`SyncResult.FAILED` при этом используется для статистики синхронизации.

---

## Полная конфигурация

Retry можно использовать вместе с остальными настройками:

```ts
provideOfflineSync({
  batchSize: 10,
  logLevel: LogLevel.ALL,
  language: LogLanguage.RU,

  retry: {
    maxAttempts: 3,
    delay: 5000,
  },
})
```
