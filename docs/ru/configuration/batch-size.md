# batchSize

**[← Назад к конфигурации](index.md)**

**Документация:** [English](../../en/configuration/batch-size.md) · [Deutsch](../../de/configuration/batch-size.md) · Русский

| Тип      | По умолчанию |
|----------|--------------|
| `number` | `1`          |

```typescript
provideOfflineSync({
  batchSize: 10,
})
```

## Зачем нужна эта опция

По умолчанию библиотека обрабатывает очередь **последовательно** — один запрос за раз: следующий запрос отправляется только после того, как предыдущий завершится (успешно или с ошибкой).

Это безопасно, но может быть медленно, если пользователь долго находился офлайн и в очереди накопилось много запросов.

`batchSize` определяет максимальное количество запросов, которые библиотека обрабатывает параллельно в рамках одного батча.

## Как это работает

**`batchSize: 1` (по умолчанию)** — запросы выполняются строго один за другим:

```
PENDING [1] [2] [3] [4] [5]
             ↓
          SYNCING [1] → COMPLETED [1]
             ↓
          SYNCING [2] → COMPLETED [2]
             ↓
             ...
```

**`batchSize: 3`** — очередь делится на батчи по 3 элемента, внутри батча запросы выполняются параллельно:

```
PENDING [1] [2] [3] [4] [5]
             ↓
     SYNCING [1] [2] [3]   (параллельно)
             ↓
   COMPLETED [1] [2] [3]
             ↓
     SYNCING [4] [5]
             ↓
   COMPLETED [4] [5]
```

Следующий батч стартует только после того, как завершится текущий.

## Когда увеличивать значение

- В очереди регулярно скапливается много запросов (например, приложение активно используется в оффлайн-режиме — склад, поле, транспорт).
- Backend выдерживает параллельные запросы от одного клиента без проблем с rate limit.
- Запросы независимы друг от друга, и порядок их выполнения не критичен.

## Когда оставить значение по умолчанию (`1`)

- Запросы зависят друг от друга по порядку (например, сначала создание сущности, затем её обновление).
- API имеет строгие ограничения по количеству одновременных запросов.
- Важна гарантированная последовательность выполнения (например, финансовые операции).

## Пример

```typescript
provideOfflineSync({
  batchSize: 5
});
```

При восстановлении соединения из очереди в 20 запросов будет сформировано 4 батча по 5 запросов. Батчи обрабатываются последовательно — по одному за раз, но с параллельным выполнением запросов внутри каждого батча.

> ⚠️ Увеличение `batchSize` ускоряет синхронизацию, но также увеличивает нагрузку на сервер в момент восстановления связи. Подбирайте значение с учётом возможностей вашего backend.
