# Priority Queue

**[← Назад к оглавлению](../../README.md)**

**Документация:** [English](../../../en/guides/configuration/priority-queue.md) · [Deutsch](../../../de/guides/configuration/priority-queue.md) · Русский

Когда приложение работает офлайн, запросы сохраняются в локальной очереди и синхронизируются после восстановления соединения.

Однако не все запросы одинаково важны.

Представим приложение интернет-магазина. Пока пользователь офлайн, могут выполняться разные действия:

* обновление профиля пользователя;
* добавление товара в корзину;
* оформление заказа;
* отправка аналитических данных.

Если все запросы имеют одинаковый приоритет, они будут обработаны в порядке очереди. Но некоторые операции важнее других — например, оформление заказа обычно должно синхронизироваться раньше, чем отправка аналитики.

**Priority Queue** позволяет задать, насколько важен тот или иной запрос.

## Уровни приоритета

Доступны три уровня приоритета:

* `HIGH` — обрабатывается в первую очередь.
* `NORMAL` — приоритет по умолчанию.
* `LOW` — обрабатывается после запросов с приоритетом `HIGH` и `NORMAL`.

## Пример

Представим приложение интернет-магазина, в котором пользователь находится офлайн.

Пользователь выполняет следующие действия:

```text
1. Отправка аналитического события   → LOW
2. Обновление профиля                → NORMAL
3. Оформление заказа                 → HIGH
4. Отправка ещё одного события       → LOW
5. Обновление корзины                → HIGH
```

Запросы добавляются в очередь в этом порядке:

```text
LOW
NORMAL
HIGH
LOW
HIGH
```

После восстановления соединения очередь обрабатывает их согласно приоритету:

```text
HIGH
HIGH
NORMAL
LOW
LOW
```

Запросы с одинаковым приоритетом сохраняют исходный порядок очереди.

## Установка приоритета запроса

Приоритет можно задать HTTP-запросу с помощью `HttpContext` из Angular:

```typescript
const context = new HttpContext().set(
  OFFLINE_SYNC_PRIORITY,
  QueuePriority.HIGH,
);

this.http.post('/api/orders', order, {
  context,
});
```

В этом примере запрос на оформление заказа получает приоритет `HIGH` и будет обработан раньше запросов с приоритетом `NORMAL` или `LOW`.

## Приоритет по умолчанию

Если приоритет не указан, запрос автоматически получает `QueuePriority.NORMAL`:

```typescript
this.http.post('/api/profile', profile);
```

Это эквивалентно:

```typescript
const context = new HttpContext().set(
  OFFLINE_SYNC_PRIORITY,
  QueuePriority.NORMAL,
);

this.http.post('/api/profile', profile, {
  context,
});
```

## Доступные приоритеты

| Приоритет              | Описание                                                      |
|------------------------|---------------------------------------------------------------|
| `QueuePriority.HIGH`   | Обрабатывается раньше запросов с приоритетом `NORMAL` и `LOW` |
| `QueuePriority.NORMAL` | Приоритет по умолчанию                                        |
| `QueuePriority.LOW`    | Обрабатывается после запросов с приоритетом `HIGH` и `NORMAL` |

Priority Queue полезен, когда в приложении есть разные типы офлайн-операций и часть запросов должна синхронизироваться раньше остальных.
